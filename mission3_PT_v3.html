def mac(pattern, filter_data): score = 0.0 for row in range(len(pattern)): for col in range(len(pattern[row])): score += pattern[row][col] * filter_data[row][col] return score
“입력받은 두 표의 같은 행과 열 위치를 곱하고 `score`에 계속 누적합니다. 모든 칸을 방문한 뒤 최종 점수를 반환합니다.”

패턴과 필터의 중요한 위치에 값이 함께 크면 곱한 값도 커집니다.

전체 합이 커짐

그런 위치가 많을수록 곱셈 결과의 총합인 MAC 점수가 커집니다.

“이 미션의 0과 1 중심 데이터에서는 패턴의 1과 필터의 1이 같은 위치에 많이 겹칠수록 1×1 결과가 많이 더해져 점수가 높아집니다. 따라서 두 필터 중 점수가 높은 쪽의 모양과 더 많이 겹친다고 판단합니다.”
정확하게는 이 미션이 정한 단순 유사도 규칙입니다. 모든 종류의 수치 데이터에서 MAC 점수가 무조건 완벽한 유사도라는 뜻은 아닙니다.

부동소수점 오차는 왜 생기며 epsilon이 왜 필요한가?

오차가 생기는 이유

컴퓨터는 소수를 이진수로 저장합니다. 0.1 같은 일부 값은 정확히 끝나는 이진수로 표현할 수 없어 아주 가까운 값으로 저장됩니다.

epsilon 정책

abs(a-b) < 1e-9이면 실제 의미상 같은 값으로 보고 동점 처리합니다.

“일부 소수는 컴퓨터의 이진 부동소수점으로 정확히 표현되지 않아 계산 뒤 아주 작은 오차가 남습니다. `==`로 완전히 같은지만 보면 사실상 동점인 값을 다르다고 볼 수 있어서, 차이가 epsilon보다 작으면 동점으로 처리합니다.”
abs()는 차이를 항상 0 이상의 크기로 만드는 Python 기본 함수이고, EPSILON은 제가 정한 비교 기준 상수입니다.

직접 수정 연습 · 입력 크기 변경

3×3 → 4×4는 input_matrix()보다 호출부의 3을 먼저 찾는다

어디를 찾나?

filter_a = input_matrix("필터 A", 3) filter_b = input_matrix("필터 B", 3) pattern = input_matrix("패턴", 3)

왜 여기인가?

input_matrix() 내부는 이미 size를 사용해 일반화되어 있습니다. 호출할 때 전달하는 3이 실제 행·열 크기를 정합니다.

“`mode1()`에서 `input_matrix(..., 3)` 세 곳을 찾겠습니다. `input_matrix()` 내부는 size로 행과 열을 검사하므로 세 호출의 3을 모두 4로 바꿉니다. 그 뒤 필터 A·B와 패턴을 각각 4줄, 줄마다 숫자 4개로 입력해 4×4 저장 완료와 점수 출력을 확인합니다.”
한 곳만 바꾸면 필터와 패턴 크기가 달라질 수 있으므로 세 호출을 함께 확인합니다. 성능표에 4×4도 보여 달라는 요구라면 성능 분석 목록도 별도로 수정합니다.
직접 수정 연습 · 라벨 표기 추가

plus도 Cross로 인정하려면 정규화 규칙을 고친다

def normalize_label(raw): text = str(raw).strip().lower() if text == "+" or text == "cross" or text == "plus": return "Cross"
“`normalize_label()`을 찾겠습니다. 이 함수가 여러 입력 표기를 Cross/X로 통일하는 곳이기 때문입니다. Cross 조건에 `plus`를 추가하고, JSON expected를 plus로 둔 사례가 Cross로 정규화되어 정상 비교되는지 실행 확인합니다.”
새로운 표기 plus는 정규화 함수만 수정하면 되지만, 새로운 모양 O는 필터 계산과 판정 구조까지 확장해야 합니다.

데이터 준비 → MAC → epsilon 판정 → expected 비교 → PASS/FAIL → 성능·요약

“이 프로그램은 모드 1에서는 사용자가 3×3 데이터를 입력하고, 모드 2에서는 JSON의 여러 패턴을 자동으로 읽습니다. 두 모드 모두 `mac()`으로 같은 위치의 값을 곱해 누적한 점수를 구하고, `decide()`에서 epsilon을 적용해 결과를 판정합니다. 모드 2는 그 판정을 정규화된 expected와 비교해 PASS/FAIL을 집계하고, 크기별 10회 평균 시간과 N² 연산 횟수를 출력합니다.”
